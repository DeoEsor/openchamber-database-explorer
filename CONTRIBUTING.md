# Contributing

Thank you for helping improve Database Explorer.

## Set up the project

Requirements: Bun and OpenChamber 2.5 or newer.

```bash
git clone https://github.com/DeoEsor/openchamber-database-explorer.git
cd openchamber-database-explorer
bun install
bun run build
bun test
```

Install the cloned directory as a local OpenChamber extension to test changes in the real panel.

## Project layout

- `src/panel/` contains the panel interface.
- `src/service/` contains the local HTTP service and PostgreSQL, MongoDB, and Redis drivers.
- `scripts/build.ts` produces the generated bundles.
- `test/` contains automated tests.
- `demo/` and `compose.yaml` provide an optional local integration environment.
- `docs/` contains guides and screenshots.

Edit source files, not `panel/main.js` or `service/main.js`; those bundles are generated by the build.

## Before opening a pull request

1. Run `bun run build` and `bun test`.
2. Test the affected workflow in OpenChamber when practical.
3. Add or update tests for driver and service changes.
4. Update documentation for user-visible behavior, limitations, DSN formats, or installation changes.
5. Keep screenshots free of real credentials, private hostnames, and sensitive data.

For database changes, prefer real integration checks using the included demo stack in addition to unit tests. MongoDB and Redis are currently read-only; preserve those guarantees unless the pull request explicitly implements and documents a safe write workflow.

## Security and credentials

Never commit real DSNs, passwords, access tokens, database dumps, or production data. Use the demo stack or disposable local credentials for development and screenshots.

Please describe the behavior changed, how it was verified, and any remaining limitations in your pull request.
